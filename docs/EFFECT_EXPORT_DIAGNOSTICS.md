# 动效导出降级诊断

不改变清晰度预算、编码候选顺序、重试次数或用户提示。事件进入现有本地 Diagnostics 日志/导出 JSON，不发送网络。

## 读取顺序

- `effectScope=INPUT_DECODE`：`DECODE_BUDGET` 给出请求画布、源/成片尺寸、Java 堆上限、当时剩余字节、解码长边预算。`DECODE_MEMORY_BUDGET` 表示预算比所选清晰度更严格，不代表已经发生 OOM。`INPUT_DECODED` 是实际解码/构图后的输入尺寸。
- `effectScope=VIDEO`：请求尺寸和可用输入尺寸、堆分档上限；每个 `CANDIDATE`；每个 AVC 编码器在本次枚举中的数字索引、能力查询/Surface/尺寸帧率拒绝或对齐结果；实际尝试及最终 `VIDEO_SAVED` 尺寸。
- `GL_LIMITS`：尝试尺寸、GL 最大纹理和 viewport 大小；仅真实超限时记 `GL_LIMIT`。
- `ATTEMPT_FAILED`：明确失败阶段和安全原因枚举。代码自己识别的超时、编码器改尺寸/格式、缺缓冲、视频不完整、保存/发布失败各自记录。平台异常仅记录类别及 CodecException 数字错误码，不根据任意异常文本猜测根因。
- `effectScope=LIVE_PHOTO`：`COVER_RETRY` 记录封面解码失败的实际尺寸及下一档尺寸，或重试耗尽；`LIVE_SAVED` 记录最初请求和最终输出。

各 scope 使用独立 operation ID，按同一时间窗口和尺寸连接，非照片标识。只有事件明确说某项拒绝/失败，才能认定该项触发；`NONE` 不是成功保证，最终 SUCCESS 才表示该阶段完成。编码能力声明不代表相册播放支持。

## 隐私和开销

不记录路径、URI、文件名、图像内容、相册包名、编码器名称、异常消息/堆栈。字段只允许固定枚举及有限范围数字。每帧仅更新失败阶段，不产生每帧日志；在阶段退出时刷新缓冲。

## 验证

新增字段的序列化/解析、未知字段和无效值过滤、异常文本不泄露、返回值/异常/取消保持不变有主机单测。设备编码器和 GL 真实失败日志仍需真机验证。
