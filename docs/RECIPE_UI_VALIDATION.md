# 配方列表与二维码弹窗验证

候选基线：`54a2bcea4db9fb7645f2633501089bcbdee47e65`，versionCode 55。没有更改 SavedPresetStore 或已有磁盘格式；未单独打包；最终提交见候选验证总览。

## 交互

- 编辑器只保留一个药剂瓶矢量图标，打开配方列表；底部增加“保存当前配方”。
- 普通点击仅选择，仍须点“应用”，原子应用、撤销及过期状态保护保留。
- 长按行显示锚定的分享/删除菜单，删除仍须确认。提供 TalkBack 自定义动作，以及菜单键/Shift+F10。
- 右上角为透明背景扫码矢量图标，进入已有相机/相册选择页；打开时不请求相机权限。
- 分享在当前 Activity 的真实 AlertDialog 展示，不启动新的展示页面；点“分享二维码图片”才打开系统分享器。只授权读取专属缓存目录内的生成 PNG。
- 对话框可取消，异步读取/生成不会在关闭后重新打开窗口；保存草稿、列表选择和二维码弹窗支持旋转恢复。
- 中文、英文、日文、韩文统一使用配方/Recipe/レシピ/레시피。胶卷出厂参数的恢复入口改称“恢复默认”，避免与用户配方混淆。

## 实际二维码显示验证

在 360×780 dp、mdpi 的真实 Robolectric ImageView 上绘制并解码，而不只读取导出的原始 PNG。

- 默认配方：245×245 px，完整解码通过。
- 全 89 项复杂配方：242×242 px，完整解码通过。
- 修复前复杂配方的 264×264 px 非整数模块缩放在该测试中无法识别；现已统一将 displayWidth 对齐为完整模块的整数像素倍数。保留完整参数与原始无损 PNG，不拆码。
- 740×320 dp 且 2 倍字体时，内容可滚动、操作按钮完整可达。该极短窗口不保证能在同一屏幕完整显示可扫码图像，分享按钮始终发送完整原始 PNG。

扫描页 Manifest 的纵向锁定已在手机和 600dp 大窗口配置验证。导入选择页不锁纵向。这不是实体折叠屏或摄像头硬件实测。

## “开窗后顿一下”的调查

不能从本轮宿主测试确定用户旧版真机卡顿的唯一原因，也不能把点“应用”时的解析错误归因于打开列表。

旧代码的 store.list 本来就在 IO 线程。使用真实私有存储路径、200 条配方、520605 字节文件，单独测量文件字节读取、JSON 树、完整读取/校验、开窗、绑定和绘制。

最后一轮宿主数据（毫秒）：

| 阶段 | 旧代码与旧资源 | 新代码与新资源 |
| --- | ---: | ---: |
| 字节读取 | 0.31 | 0.31 |
| 单独 JSON 树解析 | 19.74 | 18.90 |
| 完整存储读取与校验 | 52.51 | 49.99 |
| 冷开窗主线程 | 471.23 | 447.58 |
| 两次热开窗主线程 | 38.09 / 36.71 | 28.23 / 22.69 |

| 应用时参数与胶卷校验 | 11.31，主线程 | 10.80，IO 线程 |

这些不是手机帧时延或统计学性能对比。冷启动数据受 Robolectric 类加载、资源初始化和共享宿主负载影响，重复运行有明显波动；不能据此声称某个百分比提速。

可复现的几何结果：新增长按说明后，未修正版本在数据到达时窗口由 453px 变为 473px，说明区由 39px 变为 59px。已将最终说明从首帧展示，并把加载/空列表提示放入固定列表视口。最终断言为窗口 473→473px、说明 59→59px。旧代码搭配旧资源在相同测试中为 453→453px、39→39px，因此这不是旧版真机卡顿根因的证据。

其它实际防护：读取延后到下一帧且在后台完成；读取结果有活动窗口检查，关闭时取消；应用时的快照解析和 profile_catalog 读取移到 IO 线程，回主线程后再次检查照片/参数是否仍匹配。
