Filmroom Perf 0.1.19-opt.6 综合 GPU 实验

怎么用
1. 两个 opt.6 分包放在同一目录，保持文件名，从 .zip.001 解压，安装得到的 APK。可以更新 Filmroom Perf，不替换正式版。不要与旧分包混用。
2. 在设置里点“启用综合 GPU 实验”。然后正常导出照片，不需要运行下面的“单块诊断”。旧的精确优化选项保持不变。
3. 导出完成后看各阶段“实际后端”。GPU 后端标识才表示本次实际使用，cpu_f64 表示 CPU；同时看回退原因和是否为恢复任务。把完整诊断日志及成片观察一起发来。

这版接入什么
- 胶片曝光：原来的两次颜色矩阵运算及完整 Hanatos 光谱双三次插值。
- 镜头柔光：完整原始 PSF 的分块 FFT，不缩小柔光半径。
- 光学效果：镜头模糊、散射与光晕，保留原 FIR/IIR 方法及完整行列递推。
- 胶片显影与 DIR：原密度曲线、通道耦合、空间扩散及重新显影。
- 打印与扫描：连续的原 PCHIP 插值、纸张曝光和密度、扫描插值，表和缓冲区在阶段内复用。
这些是同一个综合测试包，不是五次独立发布。各阶段仍可单独关闭，便于对照。

没有声称什么
这不是全流程100% GPU。全局测光、原随机颗粒采样和部分颜色/空间收尾仍用 CPU。阶段之间也存在文件交接，不能把某段着色器耗时当成整个导出的耗时。
GPU 实验使用 f32，不能保证与原 f64 CPU 逐位一致。随机数生成规则没有换，但上游数值差异可能影响局部颗粒采样，最终成片误差可能大于单个插值步骤的误差。抽样数值检查不是完整画质或视觉一致性保证。
当前限定受支持的 Vulkan Adreno 路径；其他设备、显存不足、过大原始核、不安全的数值范围或运行失败会回退 CPU。不会为了进入 GPU 而降低分辨率、缩半径、换成简单插值或跳过效果。宽范围 IIR 是否可用还与系数及图像尺寸有关。

建议同图对照
先勾选“CPU 精确对照”做一次全新导出，保留成片和日志。再点“启用综合 GPU 实验”，同一张原图、胶卷、相纸、种子、尺寸和输出格式再导出一次。其余精确优化开关保持相同。
看高光边缘、暗部、渐变、细纹理、颗粒及分块接缝，也看各阶段和整个导出的时间。手机温度、后台任务、缓存和恢复任务都会影响单次耗时，不要只比较最好的一次。恢复任务会明确标注，不能当成完整重算速度。
如某阶段有异常，可只关闭该阶段再试，不必更改照片参数。

保护和日志
每个 GPU 阶段在独立辅助进程里写完整临时结果；完成校验、确认辅助进程退出后才整体采用。失败时保留原输入并整阶段回退，取消不会变成继续 CPU 重算。
新增源文件准备兼容路径：仅遇到明确不支持硬链接的系统错误且空间足够时，使用有界、可取消的原样复制。诊断记录安全的准备步骤/错误类别，不包含照片名、路径、URI、EXIF或像素。
以整个阶段和导出墙钟时间评价收益，它们包含准备及失败尝试；单独的 GPU 计算、辅助进程总计与准备时间是不同口径，不能互相替代。GPU 执行指标包含其实际传输、同步和读回，数值校验也会增加总耗时。内存准入是估计，不是手机实测峰值或系统稳定性保证。

版本边界
新实验默认关闭；更新后原有偏好可能保留。关闭新实验保留原有基线，其中旧密度 GPU 仍可能启用；勾选 CPU 精确对照才强制走 CPU 路径。解码器仍基于0.1.19，不含独立 JXL 测试版的新解码能力。正式版和原始照片不被替换。

当前已测的画质范围
主机上三组小型合成图（17×13、47×29、65×33），同参数和种子，五阶段均实际执行 f32 算法镜像，再完成原颗粒和成片收尾。与原 CPU 成片的最大绝对数值差分别约 0.000000834、0.001849、0.000438；对应 RMS 约 0.000000212、0.0000318、0.00000929。后两组包含 HDR 与负值边缘。
这些值是最终浮点颜色样本的误差，不是感知分数；不代表真实手机 GPU 的误差上限，也不保证所有照片视觉一致。没有主机测试能替代这次同图真机成片对照。尚未测得这版手机整图提速或发热数据。
