# Perf preview timing

A terminal `PREVIEW_PRESENTATION` record carries `previewTimingTerminal` plus numeric monotonic offsets. Context retains sourceToken (local counter), generation, frame kind and allowlisted settings fingerprint. `previewTimingOperation` identifies its PREVIEW_RENDER operation; it is absent for cached or pre-native cancelled work. No photo paths, photo hashes, raw input events, coordinates, exception strings or device identifiers are added.

Origin is entry to the parameter callback when available, otherwise scheduleRender entry. This is NOT the OS touch-event timestamp. SCHEDULED to DEBOUNCE_END includes scheduler delay; RENDER_QUEUED to MUTEX_ACQUIRED is mutex queue; MUTEX_ACQUIRED to WORKER_STARTED is worker scheduling; WORKER_STARTED to PREPARED includes source/asset/handle preparation and bitmap allocation. RESERVATION_REQUESTED to JNI_ENTER is admission wait, after existing native-enter diagnostic bookkeeping. JNI_ENTER to JNI_EXIT is JNI wall time, not pure GPU time. JNI_EXIT to COMPOSITION_START includes metadata/trace completion; COMPOSITION_START to ADOPTED covers composition and publication. Missing points mean not observed, NOT zero.

QUICK and REFINED have distinct contexts with the same generation and request origin. REFINED's DEBOUNCE_END includes prior QUICK/refinement settling; do not label that offset as the fixed 64ms debounce duration. Cache-only presentation has no native operation. COLD_HANDLE/WARM_HANDLE refer solely to native engine handle existence, not driver, shader, assets or source-cache temperature.

NEXT_DRAW is observed immediately after drawing the matching base bitmap in PhotoView.onDraw. It does not assert completion of other canvas drawing, SurfaceFlinger presentation, vsync delivery or photons. No observed draw within one second ends as DRAW_NOT_OBSERVED. Source/bitmap replacement never fabricates a draw. Cancellation before coroutine start, stale source/generation, cache-only and failure terminate without invented timing points. Cancelling later refinement cannot overwrite an already-adopted QUICK's pending draw observation.

Stage marks stay in a small synchronized EnumMap. Only one terminal snapshot is submitted per accumulator, via the existing bounded 16-record nonblocking queue and background diagnostic writer. Timing has a separate eight-record/second quota so ordinary adoption records do not consume its quota; suppression/drop counts remain reported. No disk write or GPU query is added to onDraw or per-stage marks. Existing native trace events are unchanged.

Validation authored: PreviewTimingHostTest covers offsets/idempotence, adoption vs display, cancellation after adoption, typed roundtrip, unknown enums and invalid numeric ranges. Not executed in this worktree: builds/tests intentionally deferred due shared disk/resource constraints. Integrator should run these plus diagnostic JSON/store tests and compile. Device checks: rapid slider edits, cancel before debounce, slow in-flight render, QUICK then REFINED, bitmap replacement/compare, background before draw, cached border edits, RAW cold/warm source. Verify terminal records correlate and contain no free text.
