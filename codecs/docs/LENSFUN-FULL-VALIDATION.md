sRGB JPEG 导出，其中 **14 张原始照片、15 个仅修改元数据的控制样本**。
全部输入文件哈希不变，probe 与 decode 的参数和警告相同，线性 RGB 均为有限数，
输出字节数和 JPEG 尺寸正确。应当保持原路径的 **22 组逐字节一致**。

## 体积与测量边界

同一 Linux x86-64 release 配置的 `libfilm_codecs.so` 从 10,743,216 bytes
变为 14,869,376 bytes，增加 **4,126,160 bytes（3.94 MiB）**。
相同 Deflate level 6 压缩参数下增加 **1,003,553 bytes（0.96 MiB）**。
这是主机 ELF/压缩数据的实测增量，**不是 Android APK 的实测增量**；
本环境没有完成 Android NDK ABI 构建和真机验证。

原始 XML 供生成、复核和来源追溯，未再复制进 App assets；运行时使用静态配置，
没有新增 Lensfun/GLib 动态库或 XML 解析器。实际 APK 增量取决于 ABI、链接裁剪、
压缩及库打包方式。生产样片按 256 MiB 内存预算和 2 GiB 磁盘预算运行，
逐项 admission 与 Linux RSS 分开记录，不能据此宣称 Android 真机内存。

完整复现命令、样片 URL、输入输出 SHA-256、受控元数据改动和源文件哈希均在
上述 JSON 中。未把完整 RAW、RGB 临时文件或测试二进制提交到仓库。
